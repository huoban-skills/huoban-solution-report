# 报告写作规范

模板骨架见 assets/template.html，本文只管「往里填什么、怎么写」。

## 全局口径

- 读者是客户决策层。语言是诊断，不是推销：陈述现状事实与后果，不喊口号，不用感叹句。
- 不用「您」「我们」「为您」等称谓，用「企业方」「双方」或直接以对象作主语。
- 名词只有两个来源：客户素材原话、平台官方名（版本与功能名以 references/platform-pricing.md 为准）。不生造行业黑话。
- 素材里没有的事实不编。缺价格、数量、日期等关键信息时写（待确认）并在交付时向用户列出清单。
- 人物称谓全篇统一（如素材里「股东」「老板」「领导」混用，先向用户确认统一叫法）。
- 涉密内容（内部系统地址、协议参数、未公开价格政策）不写入报告。

## 各章写法

**封面区**：kicker 是行业词、字间空格；主标题固定「{客户简称}数字化建议报告」，不加"服务包版"等后缀。核心目标一段四要素：以什么为切入点 → 用什么替代现状 → 达成什么可见效果 → 划出什么边界，**全段不超过 120 字**。

**一、企业与现状概览**：factlist 四条 dt 固定（行业与业务模式 / 组织规模与协作结构 / 数字化现状 / 项目目标），每条一段散文，不套卡片，**每条不超过 3 句、约 100 字**。只留支撑后文诊断的事实，经营细节与数字留给诊断卡用，不在概览里先讲一遍。数字化现状末句点出协作断点。项目目标只写一句（≤60 字）：是封面核心目标的一行浓缩，不复述边界与替代对象。

**二、核心痛点**：开场一句固定句式。诊断卡不超过 4 个，2×2 网格。卡名是名词短语（≤14 字），点出缺失或失控的对象；描述固定两句＝一句现状事实＋一句后果（能量化就量化），**合计不超过 70 字**，写成念出来有画面的人话。

**三、建设目标**：开场一句话过渡。目标不超过 4 项，每项 h3 一句动宾短语（≤16 字）＋展开**一句话**（做成什么样＋终结什么现状，≤60 字）。

**前三章总闸**：封面到第三章结束合计不超过 1200 字。同一事实全篇只出现一次：概览铺背景、诊断给后果、目标给动作，三章不互相复述。

**四、数字化解决方案**：note 说明文字模板里已固定。每个模块：

- h3 亮点标题用「功能点，业务成果」对偶（一案到底，进展留痕）；
- fn 是模块业务名；要点 3-4 条，短句，不解释原理
- 模块与诊断的对应关系必须全覆盖：每条诊断至少有一个模块回应，每个模块至少回应一条诊断，无一悬空
- 讲同一对象的多个小模块合并成一个主模块，用篇幅体现主干；边角能力不单列
- 图：成文阶段不放图也不留占位。用户确认配图后，在模块末尾追加 .fig.shot 的 img（alt 与 h3 完全一致），PNG 用 scripts/embed_figures.py 嵌入

**五、数字化实施路径**：阶段卡 2×2，通常四段：需求梳理与结构设计 → 最小闭环搭建 → 迭代扩展 → 培训与交付，按项目实际增删。每卡写清这个阶段做什么、交付什么。总周期区间写在开场句。

**六、投入与报价**：A 平台订阅的版本选择与价格查 references/platform-pricing.md；B 服务包的定价、包数建议与核销口径查 references/service-package.md。规格说明栏写该客户用得上的能力，不罗列参数。合计行只填总价。三条备注结构固定：版本选择说明 / 服务包起售与核销方式 / 后续迭代方式。

**七、预期核心业务价值**：两卡固定（对于决策层 / 对于一线团队），各 3-4 条，每条须能回扣到某条诊断或目标，不写空泛收益。

**八、下一步行动清单**：默认五条已在模板里，按项目微调。付款表述用「企业方完成付款」，不写「支付首款」。

**九、附件**：四条默认超链接已在模板里，一般不动；客户有专属附件时追加。

**尾注**：两段固定句式，只改沟通日期。

## 交付前自检

1. 全文搜 `{{`，不得残留占位符。
2. 诊断 ↔ 模块 ↔ 价值三层对应关系逐条核过，无悬空。
3. 报价数字与 reference 一致，合计算对。
4. 附件链接可点；已配图的报告，逐一核对每个模块 img 已嵌入非空 data URI。
